# Die Shift Analyze V32

## 在 Windows 一键构建

完整解压源码 ZIP。在已有 Python、PyInstaller 和运行依赖的环境中双击 **BUILD.bat**，生成 `dist\Die_Shift_Analyze.exe`。双击 **RUN.bat** 可直接运行源码。源码包保留多分辨率图标的生成代码、CUDA C 源码与驱动加载的 PTX 汇编文本。Windows 测试使用临时 EXE，Release 只提供源码与校验文件。

## RTX A5000 与混合显卡

V31 的一种现场错误是 `ModuleNotFoundError: No module named 'cupy_backends.cuda._softlink'`。它发生在 CuPy 导入阶段，即使 Windows 已列出 RTX A5000，旧版也会转为 CPU。V32 的 EXE 直接从 Windows 系统目录加载 NVIDIA 驱动 `nvcuda.dll`，用内置 PTX 执行双精度计算。运行端无需 CuPy、NVRTC、cuDNN 或 cuTENSOR。应使用支持 CUDA 12.0 PTX 8.0 的 NVIDIA 显示驱动；软件不联网安装驱动或库。机器上同时存在 AMD 显卡时，它也会出现在硬件信息中。

在“设置 → 硬件与计算资源”查看实际计算设备与通过的项目。刚体、批量姿态、型变和概率卷积分别核对 CPU 参考结果。某项没有通过或该批次超出显存预算时，用 CPU 重新计算。默认“自动”让小任务留在 CPU。拓扑和 DRC 继续使用原有几何规则。需要保留诊断时，在 EXE 所在目录运行下列命令。JSON 记录系统显卡、NVIDIA 驱动 API 版本、选择的设备、通过的项目及失败原因。

```bat
start /wait "" Die_Shift_Analyze.exe --gpu-info gpu-info.json
```

## 构建体积

BUILD.bat 完成后会打印实际 EXE 的 MiB 数及 `size-report.json` 路径。报告列出打包输入的原始大小、最大的 30 项和 EXE 的最终大小。常规输出路径为 `build\Die_Shift_Analyze\size-report.json`。构建不会自动收集本机安装的 CuPy、深度学习框架或 CUDA Toolkit DLL。定制 NumPy/SciPy 的底层数学库仍可能影响体积。

在 Windows Server x64、Python 3.13 的两次独立打包中，干净环境生成 115,360,007 字节，另一个装有 CuPy 的环境生成 115,358,180 字节，均约 110.0 MiB。两次都能在单独目录启动窗口、保留既有 Jobs 并完成 DRC 与实体概率计算。构建机显示 Microsoft Hyper-V Video；RTX A5000 的驱动与运行速度需在目标电脑上用上面的诊断复核。[Windows 验收记录](https://github.com/shiyuliuth-del/PLP_Die_Shift_Analyzer/actions/runs/41603355474)

块状刚体坐标在只有一个运动来源或纯平移时使用直接计算。确定性概率叠加按一个中心的至多四个邻接像素平移并累加过孔足迹；多角度共享旋转三角函数。线距、包围量和风险判据沿用 V31。

## GD55 同机测量

同一份 GD55 图纸有 3 颗芯片、1,225 个图形和 158 个运动过孔接口。设置 ±35 μm、±1°，线宽、线距及最小包围量均为 15 μm，良率级别 6。V31、V32 在同一台 Linux 电脑上分别使用 CPU，以正序和倒序各测一轮。下表取两轮各自中位数的中位数。

| 操作 | V31 | V32 |
|---|---:|---:|
| 158 个 Sobol 概率图 | 1.94 s | 0.95 s |
| 158 个确定性积分概率图 | 12.54 s | 3.35 s |
| 187,560 个顶点，单芯片纯平移 | 46.0 ms | 2.7 ms |
| 同一批顶点，平移叠加旋转 | 45.9 ms | 14.6 ms |

两轮 158 张 Sobol 图各像素完全一致，确定性积分的最大概率差为 $4.55\times10^{-13}$，两类图各自的全部边界以及变换后的坐标一致。[原始计时和逐项误差](../results/performance_V32.json)
