# Die Shift Analyze 与 RealDataAnalyse V59

## 双运动过孔线路

一块固定 RDL 的两端各连接一个运动过孔且没有连接固定过孔时，默认每端建立一个可编辑动区。两个过孔在同一 DIE 时，整条线跟随同一个刚体。在不同 DIE 时，两端分别跟随所属芯片。

右键可删除任一侧动区。剩下的动区按两个过孔的实际相对位姿变形，切口外的两侧各自跟随原端孔。保存工程后，重新打开可恢复这个选择。

## 孔盘和重构规则

冲突处理先尽量保留原孔盘与工艺要求的包围区域，并用真实铜完成无短路的连接。已连通的候选再尝试局部扩宽和修整内角。软件按最终铜形核验连通性、异网隔离和尺寸。若无法同时实现，画面和实测输出继续标出实际问题位置。

实际批量输出沿用 `omit_failed_regions` 策略时，只移除失败局部、保留无问题铜，并分别生成 `ERROR` 或 `ERROR2` 标记。若使用严格制造输出，则要求连接核验通过。

## 后台状态与工程

最后一个后台任务退出时，进度条和左下角实时文字同时清除。最终状态和失败原因可以在运行信息中查看。旧工程字段继续识别，旧算法的结果缓存会重新计算。

### 重点组合联合核验

SH22 的重点组合包含零位及两颗芯片的全部 729 个离散姿态。进度按已核验的姿态数量更新，耗时的补偿任务不会挡住其他姿态提交。预演与联合核验共用已生成的铜形做电连接检查，只对备用铜形追加一次核验。冲突裁切及孔盘覆盖损失使用原生整数 DBU 布尔运算，避免远坐标处近重合边引发耗时异常。复杂狭缝优先从局部坐标下的空域三角面间寻找连接，再按实际铜形检查孔盘、拓扑和异网隔离。组合较多时按硬件预算启用独立几何计算进程。子进程异常退出时，已核验的姿态保留，只重新生成和核验未返回的姿态。

## RealDataAnalyse 与 SH22 案例

两套软件共用 V59 源码包，通过 `RUN.bat` 启动，或在 Windows 上运行 `BUILD.bat` 打包。`Jobs/SH22` 保留 400 个合成封装的生产格式导入示例。按 DIE 目录导入和 ERROR、ERROR2、FAIL 分层的完整说明见 [V58 使用说明](V58_使用说明.md)。

SH22 的单独验收包可直接回读，本地文件包含原工程、合成输入、批量 OAS 和规则判定记录。
