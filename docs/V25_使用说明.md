# Die Shift Analyze V25

## 手动预演、回零与缓存

按 **M** 选芯片，右键拖动平移，滚轮旋转，Ctrl 加滚轮缩放。也可以在“极端情况”下方选 DIE，填写 DX、DY、角度后点击“预览输入”。两种入口共用姿态和动画缓存。右键连续移动时，软件在播放当前一段运动的同时保留最新的鼠标目标。多颗芯片先后输入时，已输入的其他芯片目标会保留。

手动预演会清除极端表的当前行。直接点击空白首行即可退出手动模式并回到名义位置。勾选“启用渐变插值运动”和“返回无偏移时播放渐变”时会播放回程。首行恢复全局接触判定；手动输入零仍表示查看指定姿态下的二值接触结果。

“最大缓存个数 / 工程”分别限制普通计算结果和动画包，每一类均使用这个上限。读取只更新最近使用顺序，正反向播放共用一项。动画中间帧保存在同一个包里。首次生成另一段动画也不会占用普通结果的名额。无偏移终态固定保留。运行期间可在“设置 → 缓存管理”查看当前工程和全部工程的缓存文件大小，或清除缓存。

## 宽度分析如何确定标记位置

1. 在名义固定 RDL 上找相邻孔盘、固定障碍或封装边。在两壁最近处作截面。只有同一块连通的原始线路铜穿过截面矩形的前后两端才计作一根。局部擦碰、止于矩形的线端、隔开的两根线头以及空通道不产生宽度记录。封装边距和 DRC 依然按各自的规则检查。
2. 在当前姿态重新计算这对墙面的实际边界点。矩形中心取两点的中点，方向取两点的连线。第三个刚性孔盘伸入矩形时，按完整投影保留其尺寸，分别查找相邻孔盘自身的窄口及原有线路。一个远处截面的角度不能用来定位另一对孔盘。对于连续等距壁面上相同的一束线路，合并重复取样并保留最紧的有效截面。隔开的开口、不同线路次序以及凹形障碍两侧分别评估。
3. 设原始、当前净宽分别为 $g_0,g_t$，单位均为 μm。令 $w,s$ 分别为固定 RDL 最小线宽、线距减去 DRC 容差后的有效值。$N$ 是原图中真实穿越此处的线路根数，$u_i$ 是第 $i$ 根线路在名义截面的原宽，由截面铜交段中点到原铜边界的最短距离的两倍得到。两侧各保留一道线距。

   $$
   C(g)=\max\!\left(0,\left\lfloor\frac{g-s}{w+s}\right\rfloor\right),\qquad
   W_{\mathrm{keep}}=\sum_{i=1}^{N}\max(u_i,w)+(N+1)s,\qquad
   \Delta W=\max(0,W_{\mathrm{keep}}-g_t).
   $$

   标签第一行依次给出原可通 $C(g_0)$、必过 $N$、现可通 $C(g_t)$，单位均为根。第二行给出自由线路合计需要收窄的 $\Delta W$，单位为微米。能保持原宽为绿色，需要收窄为琥珀色，低于最小线宽容量为红色。绿色仍默认隐藏。

### GD55 坐标复算

三颗 DIE 同取 DX = −35 μm、DY = −35 μm、转角 = −1°，固定线宽、线距、包围量均为 15 μm。在 (−1346.5, −464.5) μm 周围 65 μm 内，V24 有四个琥珀色标记。V25 识别出一处需要收窄的真实窄口，连接固定孔 6/0 #67 与运动孔 4/0 #102，两根原始线路穿越。矩形中心为 (−1358.397, −436.222) μm，实测净宽 145.350 μm。名义位置和八种三轴组合的统计、两端坐标和复算误差见实图记录。[GD55 九姿态记录](../results/width_V25.json)

这些数值衡量已识别通道的局部通过性。完整布通还取决于其他通道与线路之间的连接。

## 标签和设置

所有“设置”栏目初次只显示标题，点击展开。保存工程时会保留已展开的栏目。旧工程缺少这项记录时全部折叠。

在“设置 → 宽度分析 · 元素显示”中可设置“标签字号 / pt”，范围为 6–24 pt，默认 8 pt。缩放、平移、调整窗口大小后，程序按当前显示尺寸重选标签位置。标签避开所有可见窄口矩形和已经放好的标签，每端引线在图面上就近安排。附近无处摆放时暂不画文字，窄口仍可悬停查看或从宽度分析表定位。字号、显隐和栏目折叠均仅影响界面显示。

## Windows 离线启动

源码目录中双击 **RUN.vbs**，可使用已配置的 Python 环境并隐藏启动窗口。若系统已关联图形版 Python，也可双击 **main.pyw**。旧入口 **RUN.bat** 会转交给无控制台启动器。用批处理文件直接启动时，Windows 创建的命令窗口可能短暂出现。打包后的 **Die_Shift_Analyze.exe** 使用窗口模式。诊断用的 **TEST_WINDOWS.bat** 仍在终端输出结果。启动失败时使用图形提示或程序目录的 startup-error.log 查看原因。
