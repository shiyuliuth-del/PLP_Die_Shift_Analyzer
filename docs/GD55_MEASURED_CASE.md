# GD55 实测批量验证

在 RealDataAnalyse 选择源码包内的 `Jobs/GD55` 项目目录。项目自动读取 `Excel/` 下的三个工作簿，每份只有 `Measurements`。项目中的“模板图纸”默认指向 `GD55_Template.gds`。点击“创建任务”，再点击“运行 / 继续补算”。运行结束后 `Output/` 只有最终 OAS。Excel、源图及模板均为只读输入。

Excel 定义全部 36 个封装位置和每颗 DIE 的偏移与旋转。封装是 6×6 摆放，行列间距为 12000 μm。输入随编号递增，普通位置的方向、XY 和角度组合使用固定种子 510036；以三颗 DIE 的最大 `sqrt(dx² + dy² + (angle/0.035)²)` 为生成时的偏移阶梯，不是生产容限。编号 034、035、036 各包含一组实际异网孔碰接，预期局部断开并进入 FAIL。各工作簿包含全部输入值，程序直接导入这些记录。

项目 DRC 尺寸容差为 0.5 μm，最小图形面积为 1 μm²。正常生产入口的 GD55 校验读取封装姿态和位置、结束回执、ERROR/FAIL 与模板实图，并核对所有输入文件的运行前后摘要。切割道在 60000/0，MARK 在 60001/0，以模板自身坐标放入 TopCell 一次。ERROR 多边形在对应 DIE 的子 Cell 内保留方向，无法在原网格直接显出斜边时使用带实际角度的多边形引用。FAIL 只标完全断开的封装边框。

测试入口为 `tests/gui_realdata_errors.py`，可使用源码应用，也可设定 `REALDATA_TEST_EXE` 和 `DIE_SHIFT_TEST_EXE` 使用同目录的两个 Windows EXE。案例输入为合成验证数据。

## 本机实际运行

使用真实 RealDataAnalyse 导入入口与同目录预演服务，从随包 Excel 导入并计算 36 个封装。最终 OAS 的 36 个摆放坐标和 108 组姿态与 Excel 逐项一致。原三份 Excel、源图、模板在运行前后 SHA-256 一致。模板独立引用一次，切割道与 MARK 图形逐层 XOR 为空，四个文字标记保留。

034、035、036 为仅有的三个 FAIL 封装，最终轮廓逐个与真实封装边框一致。644 个 ERROR 多边形与在线 IPC 完整问题分页、项目 SQLite 目录对应。250 个直接四角多边形有斜边，80 个微小倾斜通过带实际转角的多边形引用保留。KLayout 的区域覆盖用于位置比较，gdstk 的原始多边形用于个数比较。首次回读脚本误用会合并覆盖的区域计数，已修正，并对保存的成品及该次运行采集的 36 个完整分页重新回读通过。

同一输入、工程和模板的线程基线从批次开始到最终提交用时 532.69 秒。本机独立进程版使用 6 路计算，用时 483.15 秒，约少 9%。该次过程树采样平均消耗约 3.55 个逻辑核，峰值合计 RSS 2.43 GiB。逐包及 TopCell 对比中，除 ERROR 表示变化外，全部 518 次非 ERROR 图层 XOR 为空。该组数据来自当次机器负载，Windows 冻结程序及联合主程序修订的验收由统一发布执行。
