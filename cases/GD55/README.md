# GD55-1105 联合测试案例

本目录按用户要求随两个软件一起发布。`GD55_1105.gds` 为既有GD55测试图纸；`GD55.dshift.json` 使用相对路径，保留已有用途、层序、15μm工艺及±15μm/±1°输入设置和动区编辑。解压后不要拆开这两个文件。

三份 `GD55_SYNTHETIC_DIE*.xlsx` 各对应一颗DIE，12个封装按相同文本ID匹配，4列×3行放置，间距12000μm。偏移为可复现的**合成测试值**，不是生产实测或统计样本。默认Measurements表交替使用全零位及DIE1仅X偏移1μm（DIE2/3保持零位），中心留空沿用工程；这两姿态已用于真实严格批量验证，不代表±15μm/±1°全部通过。

每份Excel另有Diagnostic表：第一封装零位，其后k=((i×(die+2)) mod 11−5)/5，dx=k/100μm、dy=−k/200μm、角度=k/10000°，i从1起。该表保留了旧算法曾触发连接失败的小偏移，作为回归压力输入；新算法修复后可以成功，不预先假定它必须失败。将列映射JSON的sheet改成Diagnostic并新建任务即可运行。实际完成/拒绝以当前软件回执为准，不能用allow_failed绕过电连接、拓扑或异网接触的硬失败，也不能把已输出当作完整DRC或生产合格。

1. 根目录 `RUN.bat` 启动 Die Shift Analyze，打开本目录 `GD55.dshift.json`，开启“输出→实测输出”，等待ready。
2. `RealDataAnalyse/RUN.bat` 启动客户端，选择服务显示的IPC入口，点击“连接 / 查询状态”，确认3颗DIE和GD55工程。
3. 选择本目录三份Excel，“校验并创建任务”保存新任务数据库。设置并发4、内存2048MB、自动重试3，选一个工作目录中的 `GD55_lot.oas`，点击运行。
4. 在KLayout打开最终OAS，TopCell应包含12个Package实例，其左下角依次为(0,0)、(12000,0)…(36000,24000)。具体完成/失败与计数看客户端和SQLite记录。

首次准备需要读取图纸、评估并规划共用动区；依硬件可能耗时。不能把窗口出现当作ready。已有服务工程与任务不符时先在手动调试页用project.open打开本案例，或关闭原实例再使用“启动同目录软件”。

本案例不会改变源GDS。服务可能更新保存的工程JSON和创建结果侧车/日志，测试前可复制整个案例到工作目录。正式包不含OAS结果或运行缓存。测量模板与严格的缺测/重复校验见 `../../RealDataAnalyse/README.md`。

在已提交的联合重构版本cef1017上，Measurements与Diagnostic各12封装均完成；Diagnostic全部12个封装逐层展开与独立单姿态GDS的XOR为空。另测两组±15μm/±1°姿态时，预览和批量接口一致拒绝已知异网接触，未生成OAS。该记录只覆盖这些姿态，最终版本验收见仓库docs/V44_VALIDATION.md。
