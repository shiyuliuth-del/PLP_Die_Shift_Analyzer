# RealDataAnalyse

与 Die Shift Analyze 同包发布的 Python/Qt 实测客户端。Windows 双击本目录 `RUN.bat`，源码使用现有环境的 pythonw，不保留命令行窗口。根目录 `BUILD.bat` 一次构建 `dist/Die_Shift_Analyze.exe` 与 `dist/RealDataAnalyse.exe`；本目录 BUILD 可单独构建客户端。两个 EXE 都是无控制台的 GUI 程序，保持同目录；只在同目录寻找预演软件，不检索系统其他程序目录。构建会将随包 `Jobs/GD55` 复制到 `dist/Jobs/GD55`，已有同名项目不会被覆盖。

## 项目文件夹

点击“选择项目文件夹”，例如根目录 `Jobs/GD55`。文件夹应包含唯一的 Die Shift Analyze 工程JSON及其相对引用的 GDS/OAS。客户端自动发现文件夹中的 `.xlsx`，读取该项目保存的勾选项、列映射与资源设置，并通过本地 IPC 联动打开对应工程；服务未运行时启动同目录程序；根据工程路径和实例身份匹配已有窗口，不自动切换其他窗口工程。同工程多个实例时应明确选择IPC入口。连接与启动按钮成功为绿色，失败为红色；详细原因在底部进度条及可选信息输出内。

项目内推荐结构：工程JSON及图纸在项目根目录，外部添加的Excel复制到 `Excel/`，任务记录在 `Tasks/`，OAS在 `Output/`，缓存由主程序保存在 `Cache/`，日志在 `logs/`。项目根目录的 `RealDataAnalyse.project.json` 保存相对路径和客户端设置。IPC认证入口是本机服务信息，仍保存在用户私有目录，不随项目复制或公开。

客户端所有工程、Excel、任务记录和输出路径必须位于所选项目文件夹内。添加外部Excel时复制原文件，相同文件名而内容不同会加摘要后缀，不覆盖原数据。删除表格行只移除引用，不删除磁盘文件。工程/输入可整目录复制到另一电脑；旧任务记录绑定原工程与运行路径，迁移后应新建任务，不能将旧回执混入新运行。旧平铺工程可先在新版主程序中另存为项目文件夹；客户端不会静默移动用户旧数据。

## Excel到OAS

1. 选择项目文件夹，等预演软件完成图纸加载和实测连接快照冻结；V47不自动进行完整方案评估或良率计算，首条偏移命令才准备路径。GD55随包提供工程、图纸与三份合成Excel，客户端不再提供生成示例按钮。
2. 在Excel表格勾选要使用的文件；每颗DIE一个Excel。可添加或删除行。
3. “Excel列映射”标题左侧checkbox默认勾选，所有文件共用一份映射；取消勾选后，点击上方Excel行切换并编辑该文件自己的映射。各文件可有不同的工作表、表头行号和列名；切回共用模式不会删除已编辑的独立映射。映射和模式随项目保存。长度为μm、角度为度；中心XY成对提供，留空沿用工程中心。未提供真实产线模板，当前适配器支持.xlsx，旧.xls须先转换。
4. 在“连接与工程”底部核对DIE数量、并发线程、内存、重试和超时（默认0，无计算超时）。“创建任务”将按文本封装ID匹配各DIE，拒绝重复、缺测、公式、非有限数值和摆放坐标冲突。全零测量保留。现有任务记录不会覆盖，新建时自动生成独立任务名。
5. “运行 / 继续补算”生成最终OAS。界面仅选择项目文件夹，工程路径自动识别，任务记录与最终OAS采用该项目内默认目录，无需输入。改变勾选项/映射/DIE数量后须新建任务。

底部连续进度条叠加当前阶段、真实计数/百分比及用时：输入摘要、Excel读取与汇入、封装匹配、服务准备、并行封装计算、OAS写入、CRC/SHA校验、原子提交。各阶段分别计进度；未知总行数时显示已读取行数，不编造总百分比。长文字自动省略，悬停可查看完整信息。信息输出默认隐藏，通过进度条左侧无文字checkbox展开（悬停有说明）；隐藏不影响实时文件日志。

## 恢复与数据边界

SQLite WAL/FULL保存输入摘要/源行号、任务状态、回执及事件；输入按文件并行、封装在磁盘关联，提交Future有界，界面每页200条。日志8MiB轮转保留8份备份。停止在安全点取消自己的批次，不强杀几何线程。

崩溃后先核对PID创建时间和冻结工程身份，确认服务已退出才重启；仍存活而无响应时停止并保留任务。未最终提交的批次完整重放；不能按computed计数跳过已丢失几何。新OAS完成计数、CRC、摘要及旧目标保护检查后才原子替换。无法解释的几何错误不通过allow_failed绕过。每个指定姿态检查完整实际铜DRC与连接，不计算无关姿态或概率；已定位的连接失败仅在明确的局部输出策略下移除，输出成功不等于生产签核。

## 手动IPC与自动化

第二页保留16个命令及JSON参数编辑：ping、info、app.start、project.open、project.close、session.prepare、output.configure、preview.submit、export.gds、batch.begin、batch.submit、batch.end、task.get、task.issues、compute.cancel、app.shutdown。支持异步等待，批次ID/任务ID自动填入模板；项目和输出目录仍限定在所选文件夹。app.start使用同目录启动规则。

自动化兼容原有入口：`python RealDataAnalyse/main.py --import-data import.json --result imported.json`，导入JSON字段为paths、database、die_count、workers及可选profile、profiles（文件绝对路径到独立映射的字典）；随后 `--run config.json --result result.json`，运行JSON字段为database、endpoint、project、output及workers、memory_mb、retries、timeout。EXE接受相同参数。这些无界面接口保持兼容已有完整路径配置。

## 计划任务、实时命令和输出整理（V48）

“创建计划任务”保存当前设置与输入摘要，可切换项目继续添加；“计划任务”面板按添加顺序运行，显示状态、进度及开始/结束时间。冲突浅黄、无效或失败浅红、完成浅绿。同项目冲突计划顺序执行，旧结果归档Cache；已完成行不重复运行。输入变化应新建计划。计划数据库位于安装目录Jobs/.RealDataAnalyse，持久任务库在项目Tasks/Plans，工程快照和临时输入在项目Cache。

成功后项目Output只保留一个最终OAS；中间OAS、partial、锁及导入暂存均位于Cache。旧结果和旧Output附属文件归档Cache/History，失败保留旧输出。每个表格下缘双线支持拖动高度，左侧行标题编号；封装记录实时刷新并展示各DIE偏移，长内容双击查看。

“实时命令信息”显示真实双向请求/回复和异常，默认2000行，可设100–10000。完整脱敏会话日志16MiB轮转保留5份；界面队列1000条，单条界面内容有上限。任务超时0不限制计算，连接仍有限超时。计划自动启动实例会安全关闭，用户已有实例保留。支持`--run-plans plans.sqlite --result result.json`执行相同队列。

## 问题封装继续与ERROR标记（V49）

批量明确请求配套预演软件的`omit_failed_regions`策略。无法重构的局部位置移除后，其他正常铜和后续封装继续输出；存在尺寸DRC但能够正常生成的铜保留并标记。客户端核对完整DRC检查、局部移除回执和实际标记计数，不把服务异常或缺失回执当成功。通信、磁盘或无法表示的非法几何仍保留任务进入恢复流程。

OAS内有实际名称为ERROR的数值层，默认从65535/0向下选择未占用层，不覆盖原图层。每个封装内的G_ERROR_封装名_DIE_编号子Cell直接保存对应DIE的矩形标记；跨DIE问题在相关DIE分别标注，无唯一DIE归属的公共问题在DIE_0。标记使用当前姿态坐标并随封装TopCell引用摆放。正常制造层保留原层号，ERROR为诊断层，输出完成不代表工艺通过。

完成记录显示“已输出（含问题）”及DRC、连接失败、ERROR矩形数；计划完成信息也保留问题计数。完整问题目录保存在项目Cache，`task.issues`可在IPC调试页分页查询，每页最多512项；单条回执仅附前128项，不代表目录截断。

随包GD55在项目的Excel目录下提供三份测量输入，每份只有Measurements。共有6×6封装及108组独立DIE姿态。客户端打开项目时自动发现Excel目录中的新工作簿，保留已保存的勾选与列映射。程序只读测量文件；计算参数采用项目内保存的DRC尺寸容差0.5 μm和最小图形面积1 μm²。已有用户项目不会被BUILD覆盖，验证新版案例请使用新源码包中的Jobs/GD55。

项目文件夹下方的“模板图纸”可选择GDS或OAS，载入成功后会保存项目相对路径。从项目外浏览选择时复制到Template目录。固定切割道、MARK图形及文字标记按模板坐标放入最终TopCell一次。任务重试、继续和计划核对模板摘要。诊断层避让模板使用的层号。批量ERROR使用四边多边形，角度在整数格点间会消失时，通过局部多边形的旋转引用保留实际方向。

批次根据封装数、CPU和内存预算选择线程或独立进程。工作队列有界，几何在独立计算路执行，OAS仍由一个有序提交端流式写入。运行日志记录使用的方式和实际并发数。

## 实测旋转与断开封装筛选（V50）

芯片边框由预演软件按各DIE实测偏移、旋转和实际旋转中心生成。ERROR使用当前问题的旋转矩形四角，客户端不重复旋转；跨DIE问题按同一实际几何分别标注到相关DIE的子Cell。

最终OAS另有FAIL层，只放存在不可修复线路断开的封装的真实封装边框，不放正常封装、仅尺寸DRC问题封装、芯片边框或铜。它随TopCell封装位置摆放，独立于单颗DIE姿态。任务、进度及计划完成信息显示FAIL封装数。缺少FAIL回执的断开输出会被拒绝，旧输出保留；旧版本未含FAIL的断开任务应新建任务，不能通过继续提交绕过此约定。
